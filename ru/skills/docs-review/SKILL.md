# docs-review

## Главные правила

1. Ничего не меняй. Только читай файлы и выполняй команды `git diff` и `git log`.
2. Не придумывай имена классов, методов, файлов, полей. Каждое имя копируй из файла, который ты открыл в этой сессии.
3. Не исправляй найденные ошибки. Только сообщи о них.

## Шаги

1. Прочитай `docs/DOCS-RULES.md` полностью.
2. Прочитай `docs/glossary.md`.
3. Прочитай `docs/MAP.md`.

   Если одного из этих файлов нет, остановись. Скажи пользователю, какого файла нет.
4. Определи измененные области по `docs/DOCS-RULES.md`, раздел 6 "Как обновлять", пункт 1.
5. Сравни изменения с `docs/DOCS-RULES.md`, раздел 5 "Когда обновлять".

   Если файл нужно было обновить, а он не изменен, запиши ошибку: "нет + где".
   Если у области нет гайдов, не записывай ошибку о гайдах. Смотри шаг 6.
6. Обрабатывай области по одной. Для каждой области выполни `docs/DOCS-RULES.md`, раздел 7 "Проверка".

   Если у области нет гайдов, это не ошибка. Не проверяй гайды этой области. Запиши область в строку "Вопросы" отчета.
7. Выведи отчет по `docs/DOCS-RULES.md`, раздел 8 "Отчет после обновления". В строке "Измененные файлы" напиши "нет".
8. Добавь в конец отчета строку `Итог: <ошибок нет / есть ошибки>`. Если есть хотя бы один пункт "нет", напиши "есть ошибки".
