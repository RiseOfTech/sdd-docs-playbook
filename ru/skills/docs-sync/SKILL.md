# docs-sync

## Главные правила

1. Изменяй только файлы в папке `docs/`. Не изменяй код программы и спецификации.
2. Не придумывай имена классов, методов, файлов, полей. Каждое имя копируй из файла, который ты открыл в этой сессии.
3. Не делай коммиты и не создавай ветки, если пользователь не попросил.

## Шаги

1. Прочитай `docs/DOCS-RULES.md` полностью.
2. Прочитай `docs/glossary.md`.
3. Прочитай `docs/MAP.md`.

   Если одного из этих файлов нет, остановись. Скажи пользователю, какого файла нет.
4. Определи измененные области по `docs/DOCS-RULES.md`, раздел 6 "Как обновлять", пункт 1.
5. Сравни изменения с `docs/DOCS-RULES.md`, раздел 5 "Когда обновлять".

   Если обновлять нечего, не меняй файлы. Перейди к шагу 7. В строке "Области" напиши "нет".
6. Обрабатывай области по одной. Для каждой области выполни `docs/DOCS-RULES.md`, раздел 6 "Как обновлять", пункты 2-7.

   Если у области нет гайдов, не создавай их. Запиши область в строку "Вопросы" отчета.
7. Выведи отчет по `docs/DOCS-RULES.md`, раздел 8 "Отчет после обновления".
