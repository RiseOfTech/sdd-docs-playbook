# sdd-docs-playbook

Библиотека рецептов для понятной и актуальной документации в проектах со SDD (spec-driven development).

Библиотеку не устанавливают. Из нее копируют шаблоны, промпты и навыки в свой проект.

> Версия 0.1. Готовы правила, шаблоны, промпты, патчи, навыки обновления и проверки, интеграция с OpenSpec и с файлами инструкций агентов. Изменения версий смотри в `CHANGELOG.md`.

## Для кого

Для аналитиков, разработчиков и тимлидов.
Готовая интеграция есть для OpenSpec. Для другого SDD-инструмента подключение описано в `ru/prompts/04-integrate.md`.

## Какую проблему решает

Новый человек открывает карту проекта. Карта показывает, какие гайды читать.
Правила записаны в одном файле. Навыки и инструкции агентов только ссылаются на него.

## Что получит проект

```
docs/
├── MAP.md            карта проекта: точка входа для нового человека
├── ONBOARDING.md     маршрут чтения по ролям
├── DOCS-RULES.md     единые правила
├── glossary.md       словарь: один термин = одно значение
└── guide/
    ├── _template/    шаблоны гайдов
    └── <область>/
        ├── analyst.md   что и зачем
        └── dev.md       как и где
```

## Как это работает

1. Один раз создай документацию: карту, словарь, правила, первые гайды.
2. Один раз подключи навыки: скопируй `docs-sync` и `docs-review`, вставь патчи в навыки проекта.
3. Затем работай как обычно.
4. После реализации изменения `docs-sync` обновляет гайды, словарь и карту.
5. Перед ревью и архивом `docs-review` проверяет документацию.
6. Если `docs-review` нашел ошибки, патч `archive.md` запрещает архив.

## Подготовка

Агент копирует файлы из библиотеки в твой проект. Поэтому агенту нужен доступ к папке библиотеки.

1. Скачай библиотеку. Положи ее рядом со своим проектом:

   ```
   ~/dev/
   ├── my-project/          твой проект
   └── sdd-docs-playbook/   эта библиотека
   ```

   Чтобы скачать через git, выполни в папке `~/dev/` команду:

   ```
   git clone https://github.com/RiseOfTech/sdd-docs-playbook.git
   ```

   Без git: на странице репозитория нажми "Code", затем "Download ZIP". Распакуй архив в папку `~/dev/`.

   Папка библиотеки должна называться `sdd-docs-playbook`. Если архив распаковался в папку с другим именем, например `sdd-docs-playbook-main` или `sdd-docs-playbook-0.1.0`, переименуй ее.
2. Открой агента в папке своего проекта. Не открывай агента в папке библиотеки.
3. Дай агенту доступ к папке библиотеки:
   - Claude Code: выполни команду `/add-dir ../sdd-docs-playbook`. Другой способ: запусти агента командой `claude --add-dir ../sdd-docs-playbook`.
   - GigaCode: выполни команду `/dir add ../sdd-docs-playbook`.
   - OpenCode и другие инструменты: добавь папку библиотеки в рабочее пространство. Как это сделать, смотри в документации инструмента.
4. Проверь доступ. Напиши агенту:

   ```
   Открой файл ../sdd-docs-playbook/ru/README.md и назови его первый заголовок.
   ```

   Если агент не может открыть файл, повтори шаг 3.

## Как запустить промпты

1. Для каждого промпта начни новую сессию агента. Тогда работа одного промпта помещается в одну сессию.
2. Напиши агенту:

   ```
   Выполни инструкцию из файла ../sdd-docs-playbook/ru/prompts/00-explore.md
   ```

3. На каждом шаге **СТОП** агент ждет твоего ответа. Проверь результат и ответь.
4. Запускай промпты по порядку:

   | Промпт | Сколько раз | Результат |
   |---|---|---|
   | `00-explore.md` | Один раз | Список инструментов, навыков и областей проекта |
   | `01-map.md` | Один раз | `docs/DOCS-RULES.md`, `docs/MAP.md` |
   | `02-glossary.md` | Один раз | `docs/glossary.md` и конфликты терминов |
   | `03-guide-area.md` | Для каждой области | Гайды области, на первой области также `docs/ONBOARDING.md` |
   | `04-integrate.md` | Один раз | Патчи в навыках проекта, навыки `docs-sync` и `docs-review` |
   | `05-audit.md` | Раз в месяц или квартал | Отчет об устаревших гайдах |

   Агент отмечает выполненные этапы в `docs/_setup/progress.md`.

   Если документация проекта уже лежит в другой папке, например `documentation/`, промпт `00-explore.md` спросит, где создать файлы. Если ты выберешь эту папку, все файлы из таблицы появятся в ней вместо `docs/`.

Для небольшого проекта используй один промпт: `ru/prompts/full-setup.md`.

## Как начать без агента

Если документация проекта уже лежит в другой папке, используй ее вместо `docs/` в шагах ниже и в скопированных файлах.

1. Создай папку `docs/` в своем проекте.
2. Скопируй `ru/templates/docs/DOCS-RULES.md` в `docs/DOCS-RULES.md`.
3. Скопируй `ru/templates/docs/MAP.md` в `docs/MAP.md`.
4. Скопируй `ru/templates/docs/glossary.md` в `docs/glossary.md`.
5. Заполни карту. Инструкция стоит в начале файла.
6. Добавь в `AGENTS.md`, `CLAUDE.md` или `GIGACODE.md` этот раздел:

   ```markdown
   ## Документация
   - Правила: `docs/DOCS-RULES.md`. Словарь: `docs/glossary.md`.
   - После изменения спецификации или поведения кода обнови гайды по `docs/DOCS-RULES.md`, раздел 6 "Как обновлять".
   - Для доменных понятий используй только термины из словаря.
   ```
7. Если в проекте есть навыки, подключи их по `ru/patches/README.md`.

## Что есть в репозитории

| Путь | Что это |
|---|---|
| `ru/templates/docs/` | Шаблоны: правила, карта, маршрут, словарь, гайды |
| `ru/prompts/` | Одноразовые задания агенту |
| `ru/patches/` | Вставки в навыки проекта. Начни с `ru/patches/README.md` |
| `ru/skills/` | Навыки `docs-sync` (обновление) и `docs-review` (проверка) |
| `ru/integrations/` | Настройка под OpenSpec и под файлы инструкций агентов |

## Планы

- Навык для добавления и переименования терминов.
- Навык, который отвечает на вопросы о проекте по карте и гайдам.
- Объяснение идеи для людей. Заметки о больших проектах и слабых моделях.
- Открытый пример проекта с документацией по этой библиотеке.
