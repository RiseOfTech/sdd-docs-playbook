# Задача: написать гайды одной области

Ты — ИИ-агент. Ты работаешь в репозитории проекта.
Прочитай эту инструкцию полностью. Затем выполняй шаги по порядку.

Запускай этот промпт отдельно для каждой области.

Цель: объяснить одну область для аналитика и разработчика.
Результат: файлы `docs/guide/<область>/analyst.md` и `docs/guide/<область>/dev.md`, ссылки на них в `docs/MAP.md`.

## Главные правила

1. Выполняй шаги строго по порядку. Не пропускай шаги.
2. На шаге с пометкой **СТОП** покажи результат пользователю. Жди ответа. Не продолжай без ответа.
3. Изменяй только папку `docs/guide/`, файлы `docs/glossary.md`, `docs/MAP.md`, `docs/ONBOARDING.md` и папку `docs/_setup/`.
   Изменяй `docs/DOCS-RULES.md` только по просьбе пользователя на шаге 10.
4. Не изменяй код программы и спецификации.
5. Не придумывай имена классов, методов, файлов, полей.
   Каждое имя копируй из файла, который ты открыл в этой сессии.
6. Если ты не уверен в факте, напиши в тексте `[ПРОВЕРИТЬ: <что именно>]`. Не угадывай.
7. Обрабатывай одну область за один раз. Закончи область, потом начинай следующую.
8. Не делай коммиты и не создавай ветки, если пользователь не попросил.
9. Если инструкция противоречит правилам проекта (`AGENTS.md`, `CLAUDE.md`, `GIGACODE.md` и т. п.), остановись и спроси пользователя.

**Корень документации.** Открой `docs/_setup/progress.md` и найди строку "Корень документации". Если файла нет, найди в проекте файл `_setup/progress.md`. Если корень документации не `docs/`:
- во всех путях этого промпта замени `docs/` на корень документации;
- в каждом тексте, который ты переносишь из библиотеки в проект, тоже замени `docs/` на корень документации.

**Если работа прервалась:** открой `docs/_setup/facts-<область>.md` и гайды области. Продолжи с первого незавершенного шага.

## Шаг 1. Прочитай результат предыдущих этапов

1. Открой `docs/DOCS-RULES.md`. Прочитай файл полностью.
2. Открой `docs/glossary.md`.
3. Открой `docs/MAP.md`.
4. Открой `docs/_setup/progress.md`.

Если одного из файлов нет, остановись. Скажи пользователю: "Сначала выполни промпт `02-glossary.md`."

## Шаг 2. Выбери область

- Если пользователь назвал область, используй ее.
- Иначе возьми первую область из таблицы "Области" в `progress.md`, у которой нет гайдов.

Если это первая область, выбери ее вместе с пользователем: средний размер, есть спецификация, понятный код.

## Шаг 3. Скопируй шаблоны

Если папки `docs/guide/_template/` нет, скопируй файлы из библиотеки `sdd-docs-playbook`:

| Откуда | Куда |
|---|---|
| `ru/templates/docs/guide/_template/analyst.md` | `docs/guide/_template/analyst.md` |
| `ru/templates/docs/guide/_template/dev.md` | `docs/guide/_template/dev.md` |

Пути `ru/...` начинаются от папки библиотеки. Обычно она лежит рядом с проектом: `../sdd-docs-playbook/`.
Если у тебя нет доступа к файлам библиотеки, остановись. Попроси пользователя дать доступ по файлу библиотеки `ru/README.md`, раздел "Подготовка". Не пиши текст файлов библиотеки по памяти.

## Шаг 4. Собери факты

1. Прочитай спецификацию области полностью, если она есть.
2. Найди точку входа: контроллер, задачу по расписанию, слушатель сообщений, публичный метод.
3. Пройди по коду от точки входа. Запиши цепочку вызовов: `Class.method()` → `Class.method()`.
4. Запиши все условия (`if`, `switch`, исключения), которые меняют результат.

Запиши факты в `docs/_setup/facts-<область>.md`. Это черновик. Пользователь его не читает.

## Шаг 5. Напиши `analyst.md`

Если область стоит в разделе "Служебные области" файла `docs/MAP.md`, пропусти этот шаг.

1. Скопируй `docs/guide/_template/analyst.md` в `docs/guide/<область>/analyst.md`.
2. Выполни инструкцию в начале файла.

## Шаг 6. Напиши `dev.md`

1. Скопируй `docs/guide/_template/dev.md` в `docs/guide/<область>/dev.md`.
2. Выполни инструкцию в начале файла.

## Шаг 7. Добавь новые термины

Если нашел новый термин, добавь его в `docs/glossary.md`. Запиши термин для отчета.

## Шаг 8. Проверь гайды

Выполни `docs/DOCS-RULES.md`, раздел 7 "Проверка". Исправь все пункты "нет".

Если гайд длиннее 60 строк, предложи пользователю разделить область. Не дели сам.

## Шаг 9. Обнови карту и маршрут

1. В `docs/MAP.md` замени "нет" в колонке "Гайды" на ссылки на гайды области.
2. Если файла `docs/ONBOARDING.md` нет, скопируй `ru/templates/docs/ONBOARDING.md` в `docs/ONBOARDING.md`. Выполни инструкцию в начале файла.
3. Если файл `docs/ONBOARDING.md` уже был и область важна для человека, который не знает проект, добавь строки области в таблицы ролей.
4. Обнови таблицу "Области" в `docs/_setup/progress.md`.
5. Если у всех областей есть гайды, отметь этап 03 в `progress.md`.
6. Если этап 04 в `progress.md` уже отмечен, удали `docs/_setup/facts-<область>.md`.

## Шаг 10. Покажи результат

Выведи отчет по `docs/DOCS-RULES.md`, раздел 8 "Отчет после обновления".

**СТОП.** Если это первая область, покажи оба гайда и результат проверки. Спроси:
1. Понятен ли `analyst.md` аналитику?
2. Достаточно ли `dev.md` разработчику, чтобы найти место изменения?
3. Что изменить в шаблонах или правилах?

Если пользователь просит изменить шаблоны или правила, измени `docs/DOCS-RULES.md` и шаблоны. Затем переделай гайды этой области.

Если это не первая область, покажи только отчет.
