# Задача: проверить, что документация не устарела

Ты — ИИ-агент. Ты работаешь в репозитории проекта.
Прочитай эту инструкцию полностью. Затем выполняй шаги по порядку.

Запускай этот промпт раз в месяц или раз в квартал.

Цель: найти гайды, которые разошлись с кодом или спецификацией.
Результат: отчет для пользователя. Гайды на этом этапе не меняй.

## Главные правила

1. Выполняй шаги строго по порядку. Не пропускай шаги.
2. На шаге с пометкой **СТОП** покажи результат пользователю. Жди ответа. Не продолжай без ответа.
3. Ничего не меняй. Только читай файлы и выполняй команду `git log`.
4. Не придумывай имена файлов и хеши коммитов. Копируй их из вывода команд и открытых файлов.
5. Если ты не уверен в факте, напиши в отчете `[ПРОВЕРИТЬ: <что именно>]`. Не угадывай.
6. Если инструкция противоречит правилам проекта (`AGENTS.md`, `CLAUDE.md`, `GIGACODE.md` и т. п.), остановись и спроси пользователя.

**Корень документации.** Это папка с файлами `MAP.md` и `DOCS-RULES.md`, обычно `docs/`. Если файла `docs/MAP.md` нет, найди в проекте файл `MAP.md` рядом с `DOCS-RULES.md`. Во всех путях этого промпта замени `docs/` на эту папку.

## Шаг 1. Собери список гайдов

1. Открой `docs/MAP.md`.
2. Для каждой области запиши: пути к коду, путь к спецификации, пути к гайдам.

Если файла `docs/MAP.md` нет, остановись. Скажи пользователю: "Сначала выполни промпт `01-map.md`."

## Шаг 2. Найди устаревшие гайды

Для каждого гайда:

1. Открой гайд. Найди строку "Проверено". Скопируй из нее дату.
2. Найди последний коммит, который изменил гайд:

   ```
   git log -1 --format=%h -- <путь к гайду>
   ```

3. Найди коммиты после него. Подставь хеш из пункта 2 и пути области:

   ```
   git log --oneline <хеш>..HEAD -- <путь к коду> <путь к спецификации>
   ```

4. Если вывод пустой, гайд не устарел. Перейди к следующему гайду.
5. Если в выводе есть коммиты, гайд устарел.

Не используй хеш из строки "Проверено". После squash или rebase этого коммита может не быть в истории.

## Шаг 3. Найди пометки

Найди все пометки `[ПРОВЕРИТЬ]` в папке `docs/guide/`. Пропусти папку `docs/guide/_template/`.

## Шаг 4. Найди области без гайдов

По `docs/MAP.md` найди области, у которых в колонке "Гайды" стоит "нет".

## Шаг 5. Выведи отчет

```
Дата: <ГГГГ-ММ-ДД>
Проверено гайдов: <N>

Устаревшие гайды:
| Гайд | Проверено | Коммиты |
|---|---|---|

Пометки [ПРОВЕРИТЬ]:
<файл — текст пометки, или "нет">

Области без гайдов:
<список или "нет">
```

**СТОП.** Покажи отчет. Спроси пользователя, какие гайды обновить. Не обновляй их сам.
