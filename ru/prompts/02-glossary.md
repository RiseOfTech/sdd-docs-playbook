# Задача: собрать словарь проекта

Ты — ИИ-агент. Ты работаешь в репозитории проекта.
Прочитай эту инструкцию полностью. Затем выполняй шаги по порядку.

Цель: собрать термины проекта.
Результат: файл `docs/glossary.md` и список конфликтов для пользователя.

## Главные правила

1. Выполняй шаги строго по порядку. Не пропускай шаги.
2. На шаге с пометкой **СТОП** покажи результат пользователю. Жди ответа. Не продолжай без ответа.
3. Изменяй только файлы `docs/glossary.md` и `docs/_setup/progress.md`.
4. Не изменяй код программы и спецификации.
5. Не придумывай имена классов, методов, файлов, полей.
   Каждое имя копируй из файла, который ты открыл в этой сессии.
6. Если ты не уверен в факте, напиши в тексте `[ПРОВЕРИТЬ: <что именно>]`. Не угадывай.
7. Обрабатывай одну область за один раз. Не держи в работе несколько областей.
8. Не делай коммиты и не создавай ветки, если пользователь не попросил.
9. Если инструкция противоречит правилам проекта (`AGENTS.md`, `CLAUDE.md`, `GIGACODE.md` и т. п.), остановись и спроси пользователя.

**Если работа прервалась:** открой `docs/glossary.md`. Продолжи со следующей области из `docs/MAP.md`.

## Шаг 1. Прочитай результат предыдущего этапа

1. Открой `docs/MAP.md`. Возьми из него список областей.
2. Открой `docs/DOCS-RULES.md`. Прочитай раздел 4 "Словарь".
3. Открой `docs/_setup/progress.md`.

Если одного из файлов нет, остановись. Скажи пользователю: "Сначала выполни промпт `01-map.md`."

## Шаг 2. Скопируй шаблон

Скопируй файл из библиотеки `sdd-docs-playbook`:

| Откуда | Куда |
|---|---|
| `ru/templates/docs/glossary.md` | `docs/glossary.md` |

Если у тебя нет доступа к этому файлу, попроси пользователя добавить его. Не пиши его текст по памяти.
Если файл уже есть в `docs/`, остановись и спроси пользователя.

## Шаг 3. Собери кандидатов

Для каждой области:
1. Прочитай спецификацию области, если она есть.
2. Открой главные классы предметной области (сущности, сервисы, DTO).
3. Выпиши существительные, которые повторяются в спецификации и в именах классов.

Не выписывай общие технические слова: "сервис", "контроллер", "репозиторий", "запрос", "ответ".
Выписывай слова предметной области. Примеры:
- выдача книг: читатель, выдача, возврат, штраф;
- каталог: книга, автор, полка.

## Шаг 4. Найди синонимы и конфликты

Для каждого кандидата:
1. Найди другие слова с тем же смыслом в спецификациях, коде, комментариях, README.
   Это синонимы. Их нужно запретить.
2. Проверь, не используется ли слово в двух разных значениях.
   Это конфликт. Его решает пользователь.

## Шаг 5. Заполни словарь

Выполни инструкцию в начале `docs/glossary.md`. Не удаляй эту инструкцию.

## Шаг 6. Проверь словарь

Выполни `docs/DOCS-RULES.md`, раздел 7 "Проверка". Используй только блок "Словарь (если изменен)". Исправь все пункты "нет".

**СТОП.** Покажи пользователю `docs/glossary.md`. Отдельным списком покажи все конфликты. Для каждого конфликта предложи 2 варианта решения. Формат:

```
Слово: <слово>
Значения: <значение 1>; <значение 2>
Вариант 1: <решение>
Вариант 2: <решение>
```

Жди решений.

## Шаг 7. Заверши этап

1. Исправь словарь по решениям пользователя.
2. Отметь этап 02 в `docs/_setup/progress.md`.
