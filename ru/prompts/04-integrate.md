# Задача: встроить документацию в процесс

Ты — ИИ-агент. Ты работаешь в репозитории проекта.
Прочитай эту инструкцию полностью. Затем выполняй шаги по порядку.

Цель: сделать так, чтобы гайды обновлялись при каждом изменении.
Результат: файл `docs/_setup/plan.md`, измененные навыки и конфиги, итоговый отчет.

Запускай этот промпт после пилотных гайдов. Гайды остальных областей можно писать позже.

## Главные правила

1. Выполняй шаги строго по порядку. Не пропускай шаги.
2. На шаге с пометкой **СТОП** покажи результат пользователю. Жди ответа. Не продолжай без ответа.
3. Изменяй только файлы из `docs/_setup/plan.md` и `docs/_setup/progress.md`.
4. Не изменяй код программы и спецификации.
5. Не копируй текст правил в навыки и конфиги. Давай только ссылку на `docs/DOCS-RULES.md`.
6. Не заменяй и не удаляй навыки проекта. Можешь только предложить замену в плане.
7. Если два навыка противоречат друг другу, запиши противоречие в план. Не исправляй сам.
8. Не придумывай имена файлов и навыков. Каждое имя копируй из файла, который ты открыл в этой сессии.
9. Если ты не уверен в факте, напиши в тексте `[ПРОВЕРИТЬ: <что именно>]`. Не угадывай.
10. Не делай коммиты и не создавай ветки, если пользователь не попросил.
11. Если инструкция противоречит правилам проекта (`AGENTS.md`, `CLAUDE.md`, `GIGACODE.md` и т. п.), остановись и спроси пользователя.

**Если работа прервалась:** открой `docs/_setup/plan.md`. Продолжи с первого невыполненного пункта.

## Шаг 1. Прочитай результат предыдущих этапов

1. Открой `docs/_setup/inventory.md`. Найди раздел "Навыки и правила агентов".
2. Открой `docs/DOCS-RULES.md`.
3. Открой `docs/_setup/progress.md`.
4. Открой файл библиотеки `ru/patches/README.md`.

Если одного из файлов в `docs/` нет или в `docs/guide/` нет ни одного гайда, остановись. Скажи пользователю: "Сначала выполни промпт `03-guide-area.md`."

Пути `ru/...` в этом промпте начинаются от папки библиотеки `sdd-docs-playbook`. Обычно она лежит рядом с проектом: `../sdd-docs-playbook/`.
Если у тебя нет доступа к файлам библиотеки, остановись. Попроси пользователя дать доступ по файлу библиотеки `ru/README.md`, раздел "Подготовка". Не пиши текст файлов библиотеки по памяти.

## Шаг 2. Реши для каждого существующего навыка

Для каждого навыка, связанного с ревью, задачами, спецификациями или документацией, выбери одно действие:

| Действие | Когда выбирать |
|---|---|
| **Оставить** | Навык не касается документации. |
| **Добавить патч** | Навык подходит под тип из таблицы в `ru/patches/README.md`. |
| **Предложить замену** | Навык уже делает похожую документацию, но хуже. |

## Шаг 3. Реши, куда встроить обновление гайдов

Выбери все подходящие строки таблицы.

| Если в проекте есть | Встрой так |
|---|---|
| `openspec/config.yaml` | По файлу `ru/integrations/openspec.md`. |
| Другой SDD-инструмент с шаблоном задач | Добавь в шаблон задач пункты из файла `ru/integrations/openspec.md`, шаг 2, ключ `tasks`. Запиши в план путь к файлу шаблона. |
| `AGENTS.md`, `CLAUDE.md` или `GIGACODE.md` | По файлу `ru/integrations/agents-md.md`. |
| Папка навыков | Скопируй `ru/skills/docs-sync/` и `ru/skills/docs-review/` в папку навыков проекта. |

Если в проекте нет SDD-инструмента, остановись. Скажи пользователю: "Библиотека рассчитана на проекты со SDD. В проекте не найден SDD-инструмент." Жди решения пользователя.

## Шаг 4. Запиши план

Создай `docs/_setup/plan.md`:

```markdown
# План встраивания

## Создать
- <файл> — <зачем>

## Изменить
- <файл> — <какие строки добавить> — <зачем>

## Навыки
| Навык | Действие | Что именно |
|---|---|---|

## Противоречия и риски
<список или "нет">
```

**СТОП.** Покажи план. Жди подтверждения или правок.

## Шаг 5. Выполни план

1. Выполняй пункты плана по одному.
2. Для каждого навыка с действием "Добавить патч" открой файл патча. Вставь его текст по инструкции в `ru/patches/README.md`.
3. Не меняй остальной текст навыков и конфигов.
4. Отмечай выполненные пункты в `docs/_setup/plan.md`.

## Шаг 6. Обнови `README.md`

Добавь в `README.md` проекта раздел:

```markdown
## Документация
- Карта проекта: `docs/MAP.md`.
- Как устроен проект для аналитика и разработчика: `docs/guide/`.
- Термины: `docs/glossary.md`.
- Правила ведения: `docs/DOCS-RULES.md`.
```

## Шаг 7. Выполни финальную проверку

1. Для каждой области проверь: есть `analyst.md` и `dev.md`. Запиши области без гайдов для отчета.
2. Выбери 3 случайных гайда. Если гайдов меньше, выбери все. Выполни для них `docs/DOCS-RULES.md`, раздел 7 "Проверка", заново.
3. Проверь: каждый измененный навык и конфиг ссылается на `docs/DOCS-RULES.md` и не копирует правила.
4. Собери все пометки `[ПРОВЕРИТЬ]` из гайдов в один список.
5. Удали черновики `docs/_setup/facts-*.md`. Оставь `inventory.md`, `plan.md`, `progress.md`.
6. Отметь этап 04 в `docs/_setup/progress.md`.

## Шаг 8. Выведи итоговый отчет

```
Создано: <файлы>
Изменено: <файлы и что добавлено>
Областей: <N>, гайдов: <M>
Области без гайдов: <список или "нет">
Терминов в словаре: <N>
Открытые вопросы ([ПРОВЕРИТЬ] и конфликты): <список>
Как пользоваться дальше:
  - после изменения: <команда или навык>
  - для ревью: <команда или навык>
```
